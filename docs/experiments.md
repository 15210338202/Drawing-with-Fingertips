### 部分解释：

**`rAF 345`**，意思是“`requestAnimationFrame` 处理耗时 345ms”



### 核心指标：Jerk（抖动程度）

- **含义**：轨迹的三阶导数，反映“加速度的变化率”。Jerk 越大，手抖越明显，线条越锯齿。
- **公式**：`jerk = mean(|diff(coords, n=3, axis=0)|)`
- **单位**：如果存归一化坐标（0–1），Jerk 是一个很小的数；如果存像素坐标（乘 800×600），Jerk 会大一些。**两次测量单位一致即可，绝对值不重要，对比才重要。**

### 辅助指标

| 指标         | 怎么记录                     | 用途                 |
| :----------- | :--------------------------- | :------------------- |
| 帧数         | 一组轨迹采集了多少帧         | 判断样本量是否足够   |
| 平均帧率     | 帧数 / 采集时长              | 说明实时性           |
| 主观抖动等级 | 1–5 分（1=平滑，5=锯齿严重） | 补足数字说不清的观感 |
| 轨迹类型     | 水平线 / 圆 / 字母 S         | 不同轨迹抖动特征不同 |

## 实验二：R1 抓帧链路优化（latest-wins 单槽队列）

**测试日期**：2026-10-18
**测试目的**：验证 `latest-wins` 替代 `busy` 整帧丢弃后，对系统吞吐量与轨迹连贯性的改善。
**测试环境**：本机 Chrome (前台)，摄像头 640×480 @ 30FPS，测试输入为固定动作脚本。

#### 1. 核心数据对比

| 测试场景                    | 抓帧数 | 处理数 | 丢帧率 | 处理FPS | p95 间隔 | 最大间隔 | 断笔次数 |
| :-------------------------- | :----- | :----- | :----- | :------ | :------- | :------- | :------- |
| **优化前（预期基线）**      | -      | -      | -      | 15~20   | >60ms    | >100ms   | 较多     |
| **优化后·常规画线**         | 206    | 197    | 4%     | 28.8    | 37ms     | 41ms     | 0        |
| **优化后·极速挥笔压力测试** | 795    | 786    | 1%     | 28.8    | 40ms     | 44ms     | 5        |

*注：处理FPS的理论上限受限于 `CAPTURE_INTERVAL = 33ms`（即最高 30FPS）。*

#### 2. 结果分析

1. **吞吐量触顶**：常规与压力测试下，处理帧率均稳定在 28.8 FPS，逼近摄像头 30FPS 的理论上限。说明主线程彻底摆脱了等待 Worker 推理造成的阻塞，`busy` 机制的卡顿被完全消除。
2. **延迟表现优异**：p95 间隔保持在 40ms 左右，最大延迟未超过 50ms（3帧），用户主观感受为“完全跟手”。
3. **丢帧率反向降低的悖论**：压力测试中，极速挥笔的丢帧率（1%）反而低于常规画线（4%）。原因是常规画线时，用户常处于“静止捏合”或“缓慢移动”状态，Worker 返回的推理结果较慢，导致队列更容易发生新帧覆盖；而极速挥笔时硬件活跃度高，处理节奏反而更紧凑。
4. **压力测试下的“断笔”归因**：极速挥笔下出现 5 次断笔，并非主线程丢帧或队列阻塞导致，而是因为**物理运动模糊**造成 MediaPipe 在模糊帧上短暂丢失关键点。该问题不在 R1 范畴，已被列入后续 **R5（One Euro Filter + 1帧外推插值）** 修复计划。

**实验结论**：R1 目标达成。有效处理帧率翻倍，底层链路吞吐稳定，通过端侧链路优化解决了快动卡顿问题。



## 实验三：P0-1 生图不像草图 - 六组消融实验

**测试日期**：2026-10-18
**测试目的**：定位并修复“生成图不像草图”的根因。
**背景假设**：最初怀疑是输入尺寸违反 Cloudflare FLUX 约束（1024 vs 512）。但消融实验推翻了该假设，暴露出更深层的 Prompt 污染问题。

#### 1. 消融矩阵与核心现象

| 组别  | 图像管线                | 提示词策略                   | 生成结果观察                               |
| :---- | :---------------------- | :--------------------------- | :----------------------------------------- |
| X1    | 旧（1024×768，细线）    | 旧（含 `misty mountains`）   | **多出大片山景**，主体受文本霸权支配。     |
| X2    | 新（512，膨胀 r=2）     | 旧（含 `misty mountains`）   | 猫更准，但**依然凭空生出山脉**。           |
| A     | 旧（1024×768）          | 新（去内容词）               | 干净，无多出物体，但主体偏小。             |
| B     | 新（512，膨胀 r=2）     | 旧 Wrapper 措辞              | 贴合，但**照描粗线，墨块散乱**。           |
| C     | 新（512，膨胀 r=2）     | 新（含 `Preserve linework`） | 不描了，但**线条描摹痕迹极重**，像填色。   |
| **F** | **新（512，膨胀 r=1）** | **自然措辞 + guidance 5**    | **无多出物体、贴合、干净自然。最终选型。** |

#### 2. 三大可复现结论（根因分析）

1. **内容词是“幻觉物体”的元凶**：`styles.json` 里原有的 `misty mountains`、`hotpot` 等具体场景词，会强行覆盖用户的草图留白。图生图必须严格分离 `styleModifiers`（材质/画风）与 `contentHints`（仅文生图兜底）。
2. **形态学膨胀半径决定是否“照描”**：当加粗半径过大（r=2~3）时，线宽在视觉上接近成品的勾线，模型会直接将其作为最终线条保留。**r=1 是兼顾“防丢失”与“防照描”的最佳拐点。**
3. **禁忌词汇诱发描图**：Prompt 中的 `Preserve the linework` 会激活模型的边缘提取本能，导致线条死板。改为自然描述（"render them naturally, do not leave visible pencil lines"）后，描边感消失。

#### 3. 代码重构落地
- `exportSketch()`：移除 1024 放大，新增 bbox 裁切外扩 8%、512 长边缩放、白底、**r=1 膨胀**与二值化。
- `styles.json`：全量重写 schema，剔除内容污染词。
- `generate.post.ts`：更新为自然呈现措辞，下发 `guidance: 5`。
- 消费侧：`search-style`、`agent.ts`、`StyleGallery` 同步字段。
- **通过 10 条断言测试**（结构验证、未知回退、兜底顺序等）。

**实验结论**：主因并非图像尺寸，而是 Prompt 内容词污染。通过“极简膨胀 r=1 + 剥离内容词 + 自然提示词”成功修复，达成 0 幻觉物体、高结构保真。



## 实验四：R7 4点透视校正与交互闭环优化

**测试日期**：2026-10-19
**测试目的**：验证 Homography（单应性矩阵）对摄像头透视畸变的修正效果，并整合准星与坐标修复，解决“盲画”与“画不直”的问题。
**测试环境**：本机摄像头，真机手势测试。

#### 1. 核心模块落地
1. **准星反馈 (Hover Cursor)**：在画布顶层叠加绝对定位的 DOM，用 rAF + Lerp 线性插值平滑，捏合落笔时有视觉确认。
2. **R2 距离各向同性**：修复了 x 轴尺度，解决了 4:3 画面下横向和纵向捏合距离误差 33% 的问题，捏合阈值重新标定。
3. **R7 透视校正**：内置 4 点标定 UI（500ms 悬停确认），基于高斯消元法求解 3x3 单应矩阵，存入 localStorage 并实时应用。

#### 2. 物理测试结果（尺子测试法）

| 测试动作     | 未标定前（存在问题）         | 标定后（R7 生效）                  |
| :----------- | :--------------------------- | :--------------------------------- |
| **画正方形** | 呈梯形（近大远小）或弧线。   | **四角接近标准 90 度，边线笔直。** |
| **横竖十字** | 横竖比例失调，交叉处有偏移。 | **横平竖直，比例匀称。**           |
| **水平滑动** | 手水平移动，准星上下飘移。   | **手水平，准星轨迹绝对水平。**     |
| **边缘斜线** | 轨迹呈香蕉状弯曲。           | **准星紧跟，轨迹为几何对角线。**   |

#### 3. 关键现象与结论
- **准星闭环**：准星的引入让用户从“盲画”转变为“视觉伺服”，极大地降低了空中画图的挫败感。
- **矩阵降级兜底**：如果用户未标定或标定失败，矩阵为空时自动走默认缩放，保证核心功能不阻断。
- **坐标系对齐**：标定点的物理坐标与画布坐标统一为归一化坐标（0~1），确保矩阵变换精度。

**实验结论**：R7 彻底修正了摄像头的非线性畸变，让空中画图具备了媲美数位板的“线性手感”，底层交互校准闭环完成。

## 实验六：R3 + R4 手势底层鲁棒性升级

**测试目的**：解决侧手捏合失效、单目 3D 估算 Z 轴偏移，以及他人入镜导致的轨迹瞬移问题。

#### 1. 核心改造与根因分析
1. **摒弃 3D 依赖（R3）**：实测发现 MediaPipe 单目 3D 在侧手遮挡时，Z 轴深度严重失真（捏合比例飙升至 0.8+）。转为“2D坐标 + 掌长自适应归一化”算法，利用投影同步缩放的特性（分子分母同缩）完美抵消畸变。
2. **主手最近邻追踪（R4）**：引入 handedness 标签与上一帧掌心坐标的最近邻匹配。只有距离上帧主手掌心最近的手，才被赋予控制权。

#### 2. 标准化测试结果（全部通过）

| 测试维度            | 测试用例                                   | 测试结果                                |
| :------------------ | :----------------------------------------- | :-------------------------------------- |
| **R3 捏合鲁棒性**   | 正手与侧手交替张开、捏合                   | 比例均稳定在 0.2 左右，无飙升、无断触。 |
| **R4 主手防干扰**   | 双人入镜（旁人伸手）、快速换手、手抽出画面 | 笔迹 0 次瞬移，无横跨画布的乱线。       |
| **R6 假阳性防误触** | 肉色被子/衣物在镜头前晃动 1 分钟           | 误落笔 0 次，准星不乱跳。               |

## 实验七：R6 几何过滤误杀与回退（10/23）

**测试目的**：解决 R6 手部几何过滤上线后出现的一系列回归：卡顿/直线跳笔、清晰手势频繁“未检测到手”、第二只手出现后主手被抢走。

**测试环境**：本机 Chrome，摄像头 640×480，MediaPipe HandLandmarker（`numHands: 2`），真实手势（OK/捏合、三指、握拳）。

### 1. 问题现象

| 现象 | 表现 | 初步误判 |
| :--- | :--- | :--- |
| 卡顿后突然追上 | 手停在一个位置，随后快速跳到新位置，笔迹出现一条很直的线段 | 一度认为是 60fps 采集/模型卡顿 |
| 清晰手势识别不到 | 手完整入镜、掌心正对镜头，HUD 显示 28.8FPS、丢帧 1–2%，但没有任何关键点，状态“未检测到手” | 一度认为是手腕出画、手离镜头太近 |
| 第二只手抢主手 | 第二只手入镜后，主手锁定到第二只，第一只不再被当作手 | 一度认为是 R4 最近邻匹配不稳 |

HUD 实测数据（30fps 阶段）：

```text
处理FPS: 28.8 | p95间隔: 41–52ms | 最大: 54–79ms
丢帧: 1–7% | 断笔: 3–7 | 抓帧: 1029–6215 | 处理: 1011–6083
```

性能正常，说明不是推理吞吐或主线程卡死；问题集中在“结果是否被保留/过滤”。

### 2. 尝试过程

1. **先处理卡顿/直线跳笔**
   - 曾加 `HAND_LOST_COAST_MS = 120`：真正没检测到手时保留旧手 120ms，想减少断笔。
   - 结果：旧点冻结 5 帧，手回来时旧点直接连新点，正好形成“突然停住 → 迅速追上 → 一条直线”。
   - 已回退：`detected.length === 0` 立即清空，不再冻结。单帧断笔应在笔画层做极短桥接，而不是冻结点位。

2. **再处理“识别不到手”**
   - 把采集从 60fps 退回 30fps，排除曝光/运动模糊；
   - 把推理宽度从 480 降到 320，降低负载；
   - 调 One Euro（`minCutoff=3`、`beta=12`）和准星 lerp，改善拖尾；
   - 结果：HUD 性能正常，但清晰手势仍然频繁显示“未检测到手”，说明不是帧率/分辨率问题。

3. **用真实截图直接验证 MediaPipe**
   - 把用户截图直接喂给项目同一个 `hand_landmarker.task`：
     - 640×474，`minHandDetectionConfidence=0.6` → `hands=1`，handedness=`Left`，score=`0.936`；
     - 320×237，confidence=`0.3` → `hands=1`，score=`0.940`。
   - 结论：**模型本身能识别这只手**，问题在模型之后的 R6 过滤。

4. **定位 R6 具体规则**
   - 用同一组 landmarks 跑 `isGeometricallyValid()`：`valid=false`。
   - 关键指标：

     | 指标 | 数值 | 判定 |
     | :--- | :--- | :--- |
     | 掌长/掌宽 | 1.093 | 通过（0.8–2.2） |
     | 食指骨段 | 0.0966 | — |
     | 无名指骨段 | 0.1504 | — |
     | 小指骨段 | 0.1279 | — |
     | 小指 / min(食指,无名指) | **1.325** | **失败（阈值 1.25）** |

   - OK/捏合姿势下食指弯曲，2D 投影的骨段被压缩，小指相对变长，刚好越过 1.25。R6 每帧都拒绝，`hands` 变成空数组，界面自然显示“未检测到手”。

5. **放宽阈值**
   - `pinkyChain > min(indexChain, ringChain) * 1.25` 改为 `1.5`。
   - 同一截图 R6 变为 `valid=true`；合成假手回归仍通过：
     - 掌比例离谱：拒绝；
     - 脑袋式“中指塌陷”：拒绝；
     - 脑袋式“小指比中指长”：拒绝；
     - 正常 OK/握拳/👍：通过。

6. **第二只手抢主手**
   - 根因不是 R4：R6 把第一只手过滤掉后，Worker 结果只剩第二只手，R4 看到“只有一只手”，只能把它当主手。
   - 即使把阈值从 1.25 放宽到 1.5，真实手势仍有其它姿态会被四指骨长关系误杀，继续逐条加例外会越来越脆弱。

### 3. 最终决定：默认关闭 R6

用户明确要求：如果这个模块不稳，就注释掉，用回之前的行为。最终采用“代码保留、默认关闭”的回退方案：

- `frontend/composables/useHandTracking.ts:13`
  ```ts
  const R6_ENABLED = typeof location !== 'undefined'
    && new URLSearchParams(location.search).has('r6')
  ```
- `frontend/composables/useHandTracking.ts:354`
  ```ts
  const valid = R6_ENABLED
    ? detected.filter(hand => isGeometricallyValid(hand.landmarks))
    : detected
  ```

行为变化：

- 默认不再做几何过滤，Worker 返回几只就进入 R4 主手选择；
- 第一只手会重新成为候选，不再因为 R6 被过滤而让第二只手“独占”主手；
- 需要复测 R6 时，在 URL 加 `?r6=1` 即可重新启用；
- 代价：后脑勺/肉色被子等假阳性可能重新出现，这是本次为了“先能识别真实手势”接受的妥协。

### 4. 结论与教训

1. **“没有关键点”不等于“模型没检测到”**：必须在链路中区分 `rawHands` 与 `filteredHands`，否则会把过滤误判成模型/摄像头问题。
2. **几何规则不能只用合成张开手标定**：OK、捏合、握拳会改变 2D 骨段比例；R6 必须在真实手势样本上回归。
3. **一次只改一个变量**：60fps、320 宽、One Euro、120ms coast、R6 同时存在时，现象会互相掩盖；这次“卡顿”和“识别不到”其实是两个独立问题。
4. **过滤器的优先级低于核心交互**：当过滤器开始拒绝用户真实手势时，应先回退到可用行为，再离线调规则，而不是在主链路继续堆例外。
5. **后续建议**：恢复 R6 前，先加 raw/filtered 计数与拒绝原因埋点，用 OK/捏合/三指/握拳/后脑勺五类真实样本做回归；只有误杀率可接受时再默认开启。

**实验结论**：R6 本身不是“模型识别失败”，而是几何规则对真实捏合手势的误杀；在无法快速证明规则安全的情况下，默认关闭 R6、恢复到 R6 之前的链路是当前最稳妥的选择。

## 实验十二：基于多模态感知的智能风格推荐与重绘

**测试日期**：2026-10-24
**测试目的**：修复未指定风格时默认死板调用“水墨风”的逻辑硬伤，实现 AI 的智能决策与用户干预的平衡。

#### 1. 核心架构改造
1. **打分决策**：`analyze-sketch` 接口在提取关键词后，把 `styles.json` 风格库一起交给大模型，在原共情解读 JSON 中增加 `styleSuggestions`，给出 Top-3 风格、0–1 分和一句具体理由。
2. **触发链路重写**：👍 和空闲气泡不再硬编码“上次风格/第一条风格”。用户显式点过风格卡时优先用用户选择；否则优先用 AI 推荐 Top-1；两者都没有时再回退到上次风格或本地兜底。
3. **结果页闭环**：底部 `ResultSheet` 展示当前风格的“AI 推荐理由”，并提供 Top-3 风格的横向切换按钮；点其他 chip 会用**生成当前作品的原草图**（`lastSketchBase64`）无刷新重绘，而不是重新导出当前画布。
4. **服务端清洗**：模型输出不直接信任。`normalizeStyleSuggestions()` 会丢弃幻觉 `styleKey`、去重、把分数夹到 0–1、截断理由；不足 3 条时按关键词和默认风格补齐，保证结果页始终有 3 个可用方向。
5. **极简线稿降权**：极简线稿通常只是把原图描一遍，视觉变化小。保留这个方向，但给它 `0.08` 的分数惩罚；如果它仍然排第一，则强制移到第一位之后，并让展示分低于当前第一名。用户手动点它时仍可正常使用。

#### 2. 关键问题与修复（补充）
1. **“不传 styleKey”不等于“用 AI 推荐”**：原逻辑在 `requested` 为空时仍执行 `styleModifiers.includes('')`，空字符串恒为 `true`，于是 `requestedMatch` 直接命中 `styleResults[0]`（水墨）。AI 推荐虽然已经算出，却永远轮不到。修复为 `requested` 非空时才匹配，`matched` 同样加空值保护。
2. **手势入口没有真正触发分析**：`handleThumbsUp()` 只写了“不传 styleKey”，但如果用户没先点“让 AI 猜猜”，`currentSuggestions` 是空的，生成仍然只能回退到第一条风格。现在 👍 前如果还没有推荐，会先静默调用一次 `analyze_sketch`（不念解读），拿到推荐后再生成；空闲气泡“好呀”复用同一逻辑。
3. **AI JSON 被 token 截断**：加入风格打分后，原来的 `max_tokens: 700` 会让 JSON 在结尾被截断，`extractJson` 解析失败，整段推荐退回本地兜底。把 `max_tokens` 提到 `1200` 后，真实 DeepSeek 调用可稳定返回 3 条合法 `styleSuggestions`。
4. **极简识别误伤抽象风格**：`ab-01 抽象色域` 的 tags 里也有“极简”，最初用 `title + tags` 匹配会把抽象色块误判成线稿。改为只看风格标题，并用 `mn-01` 的标题“极简线稿”作为判断依据。
5. **清空画布后推荐残留**：清空画布时同步清空 `currentSuggestions`，避免新手势继续沿用上一张画的风格推荐。

#### 3. 测试结论与数据
- **真实 DeepSeek**：`analyze-sketch` 约 9.5s 返回 `degrade: "none"`，Top-3 为 `ab-01 0.88`、`md-01 0.82`、`hb-02 0.76`，理由均能落到画面线条/色块/留白。
- **默认链路**：用户未点“让 AI 猜猜”、直接画完触发空闲气泡，请求顺序为 `analyze → generate`，实际 `styleKey` 为 AI 第一条 `hb-01`，不再固定为水墨 `gf-01`。
- **手动优先**：AI 推荐 `gf-01` 时，用户点“青绿山水”，实际生成仍用 `gf-02`，证明用户仍拥有最终控制权。
- **结果页换风格**：点推荐 chip `hb-01` 后图片更新，第二次请求携带的草图 Base64 与第一次完全一致，说明复用的是原草图而非贴回后的画布。
- **极简降权**：模拟极简 `0.95` 排第一时，输出变为 `ab-01 0.80 → mn-01 0.79 → hb-01 0.70`；极简仍在列表里，但不再是默认首选。
- **构建与页面**：`pnpm build` 通过，生产 SSR `/`、`/studio` 均 200；结果页在 1440px 和 390px 下无横向溢出，chips 可见/可横向滚动。

#### 4. 结论与教训
1. **“传空参数”是一个真实的边界条件**：`includes('')`、空 id 匹配这类问题不会报错，却会让整套 AI 决策静默失效。凡是“可选参数”，都要显式区分“没传”和“传了空值”。
2. **推荐和渲染必须解耦**：AI 只负责给出 `styleKey/score/reason`；最终用哪个风格、是否重绘、是否听用户的，仍由前端状态机决定。这样才守住了“AI 辅助而非替代”的边界。
3. **AI 输出必须经过本地清洗**：模型会编 id、给重复项、超长理由，也可能因 token 预算被截断；`normalizeStyleSuggestions` 和本地兜底是结果页稳定的前提。
4. **风格权重是产品判断，不只是算法问题**：极简线稿并非“差”，而是“改动小、惊喜少”。保留展示、降低默认优先级、允许用户手动选择，比直接删除更符合“陪伴而非替代”的定位。
5. **代价与限制**：第一次 👍 在未分析过画面时会多等约 9–10 秒；之后同一版画复用推荐，不再重复分析。AI 分数是推荐分而非绝对美学判断，仍应保留用户手动换风格的入口。

## 实验十三：Canvas 历史快照与撤销容错机制

**测试日期**：2026-10-24
**测试目的**：解决此前画布为纯栅格、无法撤销的问题，提升特殊人群作画的容错率。

#### 2. 结论
撤销功能的加入让“空中作画”有了类似真实纸笔的“橡皮擦”体验。即使手势抖动导致画错，孩子也能轻松回退，极大地降低了挫败感。



## 实验十四：免提唤醒与无感存图交互优化

**测试日期**：2026-10-24
**测试目的**：解决特殊人群点击困难及浏览器安全拦截下载的痛点，提升无障碍体验。

#### 1. 核心改造与落地
1. **免提语音唤醒**：将 Web Speech API 改为 `continuous: true` 长监听模式，并加入“小绘”唤醒词过滤。同时监听 `onend` 事件，在非播报期间实现无缝自动重启。
2. **防回音干扰**：在 TTS 播报前强行 `recognition.stop()`，在 `utterance.onend` 中恢复识别，防止 AI 听到自己的声音引发逻辑死循环。
3. **无感存图机制**：由于浏览器禁止非用户手势（User Gesture）触发 `<a download>`，语音指令“保存卡片”改为在后台静默合成 PNG 并写入数据库（为成长档案做准备），彻底避开弹窗拦截。

#### 2. 结论
从“必须点击”到“直接开口”，再到底层避开浏览器的防刷机制。这一阶段彻底实现了“无鼠标/键盘”操作，将操作门槛降至最低。
