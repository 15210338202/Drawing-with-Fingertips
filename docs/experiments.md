### 部分解释：

**`rAF 345`**，意思是“`requestAnimationFrame` 处理耗时 345ms”



### 核心指标：Jerk（抖动程度）

- **含义**：轨迹的三阶导数，反映“加速度的变化率”。Jerk 越大，手抖越明显，线条越锯齿。
- **公式**：`jerk = mean(|diff(coords, n=3, axis=0)|)`
- **单位**：如果存归一化坐标（0–1），Jerk 是一个很小的数；如果存像素坐标（乘 800×600），Jerk 会大一些。**两次测量单位一致即可，绝对值不重要，对比才重要。**

### 辅助指标

| 指标         | 怎么记录                     | 用途                 |
| :----------- | :--------------------------- | :------------------- |
| 帧数         | 一组轨迹采集了多少帧         | 判断样本量是否足够   |
| 平均帧率     | 帧数 / 采集时长              | 说明实时性           |
| 主观抖动等级 | 1–5 分（1=平滑，5=锯齿严重） | 补足数字说不清的观感 |
| 轨迹类型     | 水平线 / 圆 / 字母 S         | 不同轨迹抖动特征不同 |

## 实验二：R1 抓帧链路优化（latest-wins 单槽队列）

**测试日期**：2026-10-18
**测试目的**：验证 `latest-wins` 替代 `busy` 整帧丢弃后，对系统吞吐量与轨迹连贯性的改善。
**测试环境**：本机 Chrome (前台)，摄像头 640×480 @ 30FPS，测试输入为固定动作脚本。

#### 1. 核心数据对比

| 测试场景                    | 抓帧数 | 处理数 | 丢帧率 | 处理FPS | p95 间隔 | 最大间隔 | 断笔次数 |
| :-------------------------- | :----- | :----- | :----- | :------ | :------- | :------- | :------- |
| **优化前（预期基线）**      | -      | -      | -      | 15~20   | >60ms    | >100ms   | 较多     |
| **优化后·常规画线**         | 206    | 197    | 4%     | 28.8    | 37ms     | 41ms     | 0        |
| **优化后·极速挥笔压力测试** | 795    | 786    | 1%     | 28.8    | 40ms     | 44ms     | 5        |

*注：处理FPS的理论上限受限于 `CAPTURE_INTERVAL = 33ms`（即最高 30FPS）。*

#### 2. 结果分析

1. **吞吐量触顶**：常规与压力测试下，处理帧率均稳定在 28.8 FPS，逼近摄像头 30FPS 的理论上限。说明主线程彻底摆脱了等待 Worker 推理造成的阻塞，`busy` 机制的卡顿被完全消除。
2. **延迟表现优异**：p95 间隔保持在 40ms 左右，最大延迟未超过 50ms（3帧），用户主观感受为“完全跟手”。
3. **丢帧率反向降低的悖论**：压力测试中，极速挥笔的丢帧率（1%）反而低于常规画线（4%）。原因是常规画线时，用户常处于“静止捏合”或“缓慢移动”状态，Worker 返回的推理结果较慢，导致队列更容易发生新帧覆盖；而极速挥笔时硬件活跃度高，处理节奏反而更紧凑。
4. **压力测试下的“断笔”归因**：极速挥笔下出现 5 次断笔，并非主线程丢帧或队列阻塞导致，而是因为**物理运动模糊**造成 MediaPipe 在模糊帧上短暂丢失关键点。该问题不在 R1 范畴，已被列入后续 **R5（One Euro Filter + 1帧外推插值）** 修复计划。

**实验结论**：R1 目标达成。有效处理帧率翻倍，底层链路吞吐稳定，通过端侧链路优化解决了快动卡顿问题。



## 实验三：P0-1 生图不像草图 - 六组消融实验

**测试日期**：2026-10-18
**测试目的**：定位并修复“生成图不像草图”的根因。
**背景假设**：最初怀疑是输入尺寸违反 Cloudflare FLUX 约束（1024 vs 512）。但消融实验推翻了该假设，暴露出更深层的 Prompt 污染问题。

#### 1. 消融矩阵与核心现象

| 组别  | 图像管线                | 提示词策略                   | 生成结果观察                               |
| :---- | :---------------------- | :--------------------------- | :----------------------------------------- |
| X1    | 旧（1024×768，细线）    | 旧（含 `misty mountains`）   | **多出大片山景**，主体受文本霸权支配。     |
| X2    | 新（512，膨胀 r=2）     | 旧（含 `misty mountains`）   | 猫更准，但**依然凭空生出山脉**。           |
| A     | 旧（1024×768）          | 新（去内容词）               | 干净，无多出物体，但主体偏小。             |
| B     | 新（512，膨胀 r=2）     | 旧 Wrapper 措辞              | 贴合，但**照描粗线，墨块散乱**。           |
| C     | 新（512，膨胀 r=2）     | 新（含 `Preserve linework`） | 不描了，但**线条描摹痕迹极重**，像填色。   |
| **F** | **新（512，膨胀 r=1）** | **自然措辞 + guidance 5**    | **无多出物体、贴合、干净自然。最终选型。** |

#### 2. 三大可复现结论（根因分析）

1. **内容词是“幻觉物体”的元凶**：`styles.json` 里原有的 `misty mountains`、`hotpot` 等具体场景词，会强行覆盖用户的草图留白。图生图必须严格分离 `styleModifiers`（材质/画风）与 `contentHints`（仅文生图兜底）。
2. **形态学膨胀半径决定是否“照描”**：当加粗半径过大（r=2~3）时，线宽在视觉上接近成品的勾线，模型会直接将其作为最终线条保留。**r=1 是兼顾“防丢失”与“防照描”的最佳拐点。**
3. **禁忌词汇诱发描图**：Prompt 中的 `Preserve the linework` 会激活模型的边缘提取本能，导致线条死板。改为自然描述（"render them naturally, do not leave visible pencil lines"）后，描边感消失。

#### 3. 代码重构落地
- `exportSketch()`：移除 1024 放大，新增 bbox 裁切外扩 8%、512 长边缩放、白底、**r=1 膨胀**与二值化。
- `styles.json`：全量重写 schema，剔除内容污染词。
- `generate.post.ts`：更新为自然呈现措辞，下发 `guidance: 5`。
- 消费侧：`search-style`、`agent.ts`、`StyleGallery` 同步字段。
- **通过 10 条断言测试**（结构验证、未知回退、兜底顺序等）。

**实验结论**：主因并非图像尺寸，而是 Prompt 内容词污染。通过“极简膨胀 r=1 + 剥离内容词 + 自然提示词”成功修复，达成 0 幻觉物体、高结构保真。



## 实验四：R7 4点透视校正与交互闭环优化

**测试日期**：2026-10-19
**测试目的**：验证 Homography（单应性矩阵）对摄像头透视畸变的修正效果，并整合准星与坐标修复，解决“盲画”与“画不直”的问题。
**测试环境**：本机摄像头，真机手势测试。

#### 1. 核心模块落地
1. **准星反馈 (Hover Cursor)**：在画布顶层叠加绝对定位的 DOM，用 rAF + Lerp 线性插值平滑，捏合落笔时有视觉确认。
2. **R2 距离各向同性**：修复了 x 轴尺度，解决了 4:3 画面下横向和纵向捏合距离误差 33% 的问题，捏合阈值重新标定。
3. **R7 透视校正**：内置 4 点标定 UI（500ms 悬停确认），基于高斯消元法求解 3x3 单应矩阵，存入 localStorage 并实时应用。

#### 2. 物理测试结果（尺子测试法）

| 测试动作     | 未标定前（存在问题）         | 标定后（R7 生效）                  |
| :----------- | :--------------------------- | :--------------------------------- |
| **画正方形** | 呈梯形（近大远小）或弧线。   | **四角接近标准 90 度，边线笔直。** |
| **横竖十字** | 横竖比例失调，交叉处有偏移。 | **横平竖直，比例匀称。**           |
| **水平滑动** | 手水平移动，准星上下飘移。   | **手水平，准星轨迹绝对水平。**     |
| **边缘斜线** | 轨迹呈香蕉状弯曲。           | **准星紧跟，轨迹为几何对角线。**   |

#### 3. 关键现象与结论
- **准星闭环**：准星的引入让用户从“盲画”转变为“视觉伺服”，极大地降低了空中画图的挫败感。
- **矩阵降级兜底**：如果用户未标定或标定失败，矩阵为空时自动走默认缩放，保证核心功能不阻断。
- **坐标系对齐**：标定点的物理坐标与画布坐标统一为归一化坐标（0~1），确保矩阵变换精度。

**实验结论**：R7 彻底修正了摄像头的非线性畸变，让空中画图具备了媲美数位板的“线性手感”，底层交互校准闭环完成。
