# 风格知识库：字段规范与收集指南

> 给**邝思绮**看的操作手册。改完 `frontend/server/data/styles.json` 后，**必须跑一次校验**：
> ```bash
> node scripts/validate-styles.mjs
> ```
> 出现「✓ 全部通过」才算完成；有「✗ 错误」就按提示改，改不动的问华雪峰。

---

## 一、先理解一件事：这个库只负责「画风」，不负责「画什么」

2026-10-18 做过一组对照实验（P0-1 消融），结论直接决定了字段怎么设计：

| 实验组 | 输入 | 结果 |
| :--- | :--- | :--- |
| A | 1024×768 细线草图 + 旧提示词 | 生成的**不是**草图那只猫，是另一只"写实猫" |
| B | ≤512 加粗草图 + 旧提示词 | **忠实复刻了草图的形状** |
| X2 | ≤512 加粗草图 + 含 `misty mountains` 的旧画风提示词 | 形状对了，但**背景被硬塞进了水墨山峦** |

**三条结论：**

1. **画什么（猫/狗/房子）由孩子的草图决定**，知识库管不了也不该管；
2. **画风（水墨/水彩/像素）由 `styleModifiers` 决定**；
3. **`styleModifiers` 里一旦出现"山、猫、面具、街道"这类名词，它就会真的被画进画面**（X2 组）。

所以下面这条是**最重要的一条规矩**：

> ### 🚫 `styleModifiers` 里绝对不能出现「画什么」
> 只写"怎么画"——材质、笔触、色彩、光影、构图方式。
> 想写"适合画什么"，请写到 `contentHints` 或 `themes` 里。

## 二、一条风格长什么样

```jsonc
{
  "id": "hb-01",                        // 唯一。格式：两位小写字母-两位数字
  "title": "绘本蜡笔",                   // 卡片标题，≤8 字最好，最多 12 字
  "category": "绘本",                    // 大类（流派/地域），见第三节的允许列表
  "tags": ["绘本", "蜡笔", "童趣", "手绘", "crayon"],   // 检索用，2–6 个，只放画风词
  "themes": ["动物", "日常", "幻想"],     // 适合画什么题材，见第三节的允许列表
  "styleModifiers": "children's picture book illustration, waxy crayon texture, thick uneven outlines, warm pastel palette, playful hand-drawn feel",
  "contentHints": "a small round animal sitting on grass",   // 只给"纯文字生成"兜底用
  "negative": "photo, realistic, 3d render",                 // 可选，见第五节
  "source": "自建",                      // 出处，如「自建·川渝文化」
  "styleKey": "picturebook-crayon"       // 生成链路按它找风格，全库唯一
}
```

### 各字段一句话说明

| 字段 | 必填 | 写什么 | 谁在用 |
| :--- | :--- | :--- | :--- |
| `id` | ✅ | 唯一编号 | 检索结果、日志 |
| `title` | ✅ | 中文卡片标题 | 界面显示 |
| `category` | ✅ | 大类：流派或地域 | 界面分组 |
| `tags` | ✅ | **画风词**，中文 + 英文别名 | **检索打分靠它** |
| `themes` | ✅ | **题材词**：这个画风适合画什么 | 前端「你想画什么」筛选；也以 0.35 低权重参与检索兜底 |
| `styleModifiers` | ✅ | **纯画风**英文描述 | 喂给图像模型 |
| `contentHints` | ✅ | **一个**场景的英文短语 | 只在纯文字生成时用 |
| `negative` | ⬜ | 不想要的东西 | **当前模型不支持，可以留空** |
| `source` | ✅ | 出处 | 界面可解释性 |
| `styleKey` | ✅ | 唯一英文键 | 生成链路解析 |

## 三、两个受控词表（不能自造）

### `category`（大类：**18 个，分 5 族**）

| 族 | 大类 | 说明 |
| :--- | :--- | :--- |
| **东方传统** | 国风 / 川渝 / 民俗 | 水墨工笔、川渝文化、年画剪纸版画 |
| **西方古典与近代** | 古典西画 / 印象派 / 油画 | 文艺复兴→巴洛克→写实、印象与后印象、厚涂油画 |
| **现代与当代** | 现代主义 / 抽象 / 超现实 / 波普 / 极简 | 立体野兽表现、色域抽象、达利马格利特、沃霍尔、线稿留白 |
| **童趣与治愈** | 绘本 / 治愈 / 梦幻 / 水彩 | 儿童插画、软萌、星空发光、水彩晕染 |
| **数字与亚文化** | 二次元 / 像素 / 赛博 | 日系动画、8/16-bit、赛博朋克 |

> **为什么把"流派"和"媒材"混在同一层**：因为孩子会想"我要**水彩**的"，也会想"我要**国风**的"。
> 这一层是「用户选风格时的心理入口」，不是艺术史分类——按艺术学硬分反而找不到东西。
> 真正的艺术史脉络放在 `styleModifiers` 与 `title` 里（例如"印象派"下面可以有"点彩"和"后印象"两条）。
>
> ⚠️ **常见错误**：「文艺复兴的抽象派」不存在——文艺复兴（14–16 世纪）追求极致写实，
> 抽象派（20 世纪初）正是要推翻它，两者相差五百年且互相矛盾。
> 想要古典质感就选 `古典西画`，想要色块线条就选 `抽象`。


### `themes`（题材：适合画什么）

```
动物 / 人物 / 自然 / 风景 / 城市 / 静物 / 抽象 / 幻想 / 日常 / 传统 / 未来 / 游戏
```

> **`themes` 参与检索吗？** 参与，但只有 **0.35** 的低权重（低于任何真实风格词的 0.6/1.0）。
> 所以搜「动物」能召回一批画风，但搜「水墨」不会被题材词干扰。
>
> ⚠️ **「动物」是 `themes` 的一个值，不是 `category`。**
> 因为 `category` 是"流派/地域"，`themes` 是"题材"——两个维度不能混。
> 一个「水墨国风」可以同时适合画动物、风景、人物，它是同一个画风下的不同题材。

## 四、收集优先级（做不完也能交）

### 🥇 第一优先 —— 先交 15 条

1. **含「动物」题材的画风**：现在库里 **0 条**。低龄儿童画得最多的就是小猫、小狗、小恐龙。
2. **童趣与治愈族**：`绘本` / `治愈` / `梦幻` / `水彩`

### 🥈 第二优先

3. **`抽象` / `超现实`**：这两个是"不依赖具象表达"的核心，也是本项目立意最需要的一族。
4. **东方传统族**：`国风` / `民俗`

### 🥉 第三优先

5. **西方古典与近代**：`古典西画` / `印象派` / `油画`
6. **数字与亚文化**：`二次元` / `像素` / `赛博`
7. **现代与当代剩下的**：`现代主义` / `波普` / `极简`

目标：**18 类 × 4–6 条 ≈ 80–100 条**。宁少勿凑——两条几乎一样的风格不加分，
反而让检索结果看起来重复。

> ### 立意说明（写 PPT / 讲稿时用这个版本）
>
> ❌ **不要说**"自闭症患者眼中的世界是抽象的"——这是无依据的刻板印象，
> 而且把人病理化了，答辩一问"有文献支撑吗"就答不上来。
>
> ✅ **要说**："有些孩子的表达**不依赖具象**。抽象、超现实这些画风不要求'画得像'，
> 正好接住这类表达——我们不是纠正他们，而是**接住**他们。"
>
> 这个版本不需要任何医学依据，是纯产品逻辑，也和"不评判"的设计红线完全一致。

## 五、会被校验器拦住的三类错误

### ❌ 错误 1：`styleModifiers` 里写了名词（最常见）

```jsonc
// ❌ 错的
"styleModifiers": "ink wash painting of a panda by a river, rice paper texture"
```
→ 校验报错：*出现题材词「panda」——画什么由草图决定，这类词会漏进画面当内容*

```jsonc
// ✅ 对的：拆成两半
"styleModifiers": "ink wash painting, rice paper texture, visible brush strokes, monochrome wash",
"contentHints": "a panda sitting by a river"
```

### ❌ 错误 2：`contentHints` 里塞了好几个场景

```jsonc
// ❌ 错的：分号一拼，纯文字生成会画出怪东西
"contentHints": "a cute panda; a bird on a branch; a swimming koi"
// ✅ 对的
"contentHints": "a cute panda sitting on a rock"
```

### ❌ 错误 3：`tags` 和 `themes` 写反了

```jsonc
// ❌ 错的：把题材当检索词，查"国风"就再也匹配不到了
"tags": ["动物", "自然"]
// ✅ 对的
"tags": ["绘本", "蜡笔", "童趣"], "themes": ["动物", "自然"]
```

## 六、`negative` 不用花精力

`negative`（负面提示词）在当前使用的 Cloudflare 模型上**没有对应参数、根本不会被发送**。
留着这个字段只是为了将来换模型时能立刻用上。

> **所以：不用为每条风格琢磨负面词。** 写个通用的 `"photo, realistic, 3d render"` 就够了，
> 或者干脆不写。把时间花在 `styleModifiers` 和 `themes` 上，那才是真正影响出图的。

> "我们没有把『动物』做成一个分类——因为对孩子来说，重要的不是"我画的是猫还是狗"，

## 九、怎么收集：填一张 CSV，**不要碰 JSON**

> 你不需要打开 `styles.json`，也不需要懂 JSON 语法。

### 三步

1. 双击打开 `docs/styles-collect.csv`（Excel 或 WPS 都行；**已处理编码，中文不会乱码**）
2. 一行填一条风格，按下面 9 列填
3. 填完发给华雪峰，他跑两条命令就合并进去

### CSV 的 9 列

| 列 | 填什么 | 注意 |
| :--- | :--- | :--- |
| 序号 | 随便填或留空 | 脚本会自动重新编号，**不要自己管 id** |
| 名称 | 中文卡片标题 | ≤12 字，最好 ≤8 字 |
| 大类 | 从 11 个里选**一个** | 流派/地域，**不是题材** |
| 题材 | 从 12 个里选，多个用顿号隔开 | **「动物」只能出现在这一列** |
| 检索关键词 | 3–6 个，顿号隔开，可加英文别名 | 用户可能会这么说，就值得加 |
| 画风中文描述 | 中文描述**怎么画**：材质 / 笔触 / 色彩 / 光影 / 构图 | **不要写"画什么"**，写了会漏进画面 |
| 内容中文示例 | 一句话：这画风适合画什么 | 只给"纯文字生成"兜底用 |
| 来源 | `自建` 或参考链接 | 界面会显示"参考了：xxx（来源）" |
| 备注 | 写给自己看 | 不影响出图 |

### 英文不用你写

`styleModifiers` 和 `contentHints` 是英文的，但**由脚本调用 DeepSeek 自动翻译生成**，
生成后还会**强制过滤**"猫/狗/山/房子/面具"这类题材名词（就是 X2 组的那个坑）。
**你只写中文。**

### 三条硬规矩

1. **画风中文描述里不能出现具体东西**——小猫、小狗、山、房子、面具、街道、火锅都不行；
   想问"这种画风适合画什么"，写到「内容中文示例」。
2. **名称不要重复**，同一大类下不要放两条几乎一样的风格。
3. **题材只用词表里的 12 个词**：`动物 人物 自然 风景 城市 静物 抽象 幻想 日常 传统 未来 游戏`。
   不要自造（比如"猫咪"要写成"动物"）。

### 华雪峰这边怎么合并

```bash
node scripts/styles-from-csv.mjs          # ① 生成 styles.next.json 供审阅
node scripts/styles-from-csv.mjs --apply  # ② 确认后合并（自动备份到 .tmp-ablation/）
node scripts/validate-styles.mjs          # ③ 最后校验
```

> `--no-ai` 可以在没网/不想调 API 时跑，英文会留空并逐条标出来，但此时 `--apply` 会被拒绝。
